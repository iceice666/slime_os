# Bounded TCP networking for the ROS 2 Zenoh demo

## Context

The userspace virtio-net LinkDevice and exact-destination authority are already
connected in `sel4-io-tcp`: generation-declared smoltcp interface configuration
exchanges Ethernet/ARP/IPv4/ICMP traffic. Application TCP/UDP payloads are still
absent; the current gate expects `tcp=0`, and capability creation or logical
packet counters do not establish a transport.

This epic completes the short-term bounded TCP facilities for the ROS 2 Zenoh
demo, keeping network mechanisms separate from the middleware session and CDR
implementation. The owning plan is
[Network data plane](../../docs/plans/network-data-plane.md).

## Scope

- External TCP client bytes through LinkDevice remain owned by
  `01a08ff0-0bae-741e-9318-331fdafe0b96`; preserve its narrow no-listener boundary.
- Exact listener/accept, real local TCP at the demo's `127.0.0.1:7447`, application
  bindings, readiness, budgets and fault/restart settlement are owned by
  `01a0ddaa-825f-7309-8508-ed49ffe33a8d`.
- Broader authority-compatible smoltcp coverage is a separate follow-on epic,
  `01a0ddaa-8676-7d7e-8faf-47285166731f`, not a prerequisite for the short-term demo.
- Zenoh session/framing, ROS/CDR and actual external middleware interoperability
  remain with their existing ROS work items. QEMU or loopback proves no physical
  NIC, board boot or DMA containment.

## Exit conditions

Both TCP implementation slices must close on their own observed evidence: exact
bidirectional bytes with an external peer under QEMU, then two separately
authorized local components connected through TCP listen/accept and loopback,
including denied authority, backpressure, timeouts and fault/restart resource
reclamation. A capability-only path, `tcp=0`, normal shutdown alone, or a planning
change cannot close this epic. Broad smoltcp coverage is not required here.
