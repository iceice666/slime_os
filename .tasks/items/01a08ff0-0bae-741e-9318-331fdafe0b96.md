# QEMU TCP client byte stream over virtio-net: ARP, IPv4, ICMP echo reply, TCP open/send/recv/close to one declared destination

## Context

The `sel4-io-tcp` composition already binds `network-service` to
`virtio-net-driver` over IO0 rings and runs a generation-configured smoltcp
interface for ARP, IPv4 and ICMP echo reply. TCP remains unfinished: the service
polls an empty SocketSet, CONNECT only creates a capability, SEND/RECV only check
rights and count operations, and the current gate explicitly expects `tcp=0`.

This item must create a real TCP client socket to one exact generation-declared
destination. The service's address and MAC remain generation data
(`contracts/network-interface/v1`), its tick rate comes from clock authority, and
application bytes must traverse client IO0 payload queues/slices, not just the
56-byte request and 24-byte completion control messages. The frame-level QEMU
peer observes traffic at the driver boundary; capability success and logical
packet counts are not evidence of bytes on the link.

No UDP, DNS, listen/accept, IPv6, or DHCP. Backend independence is not claimed: one backend
is exercised.

## Required stream semantics

- Map each holder-bound capability to a real socket and bounded RX/TX buffers;
  complete connect only with an explicit success/failure result.
- Implement actual byte counts, partial reads/writes, backpressure/WouldBlock,
  EOF, close/reset and connect timeout; stream chunks are not message boundaries.
- Enforce declared queue/byte/socket/timer/retry ceilings in the payload path and
  return its leases and charges on teardown. Broader interrupted-request,
  driver/service/client restart qualification remains mandatory in the follow-on
  `01a0ddaa-825f-7309-8508-ed49ffe33a8d`.
- Retain explicit rejection of missing or wrong destination, transport, port,
  direction and holder authority before forbidden traffic leaves the service.

The listener/loopback and ROS runtime prerequisite is tracked separately by
`01a0ddaa-825f-7309-8508-ed49ffe33a8d`. The observations below supersede the
pre-implementation context above; follow-on requirements are not claimed here.

## Exit conditions

Under QEMU, `just io_tcp_check` observes: the service reports its declared interface and a
link that is up, answers the peer's ARP request and ICMP echo requests, opens a TCP
connection to the declared destination, sends 4096 bytes and receives them back byte for
byte, closes it, is refused by the peer on a second declared port, refuses an undeclared
destination before any frame leaves, and the plane ends healthy; `just io_link_check`
stays green; the intruder's refusals hold with zero frames at the peer.

`just io_tcp_check` and the TCP arm of `just io_network_check` each observed a
real handshake, 4096 application bytes echoed byte-for-byte, partial writes,
FIN closure, peer reset refusal on declared port 4243, and undeclared address
and port refusals. The external peer independently reconstructed both streams
from checksum-validated TCP packets and observed all 4096 bytes acknowledged,

echo segment; transmitted bytes were never replaced by a fixture-only result.

The service released both service-owned application buffers and had no live
application connection handles at shutdown. The separate nontransferable
control and transferable provisioning endpoints retain per-holder authority;
the intruder's exact-destination and independent-right refusals remained valid
without forbidden network traffic. TIME-WAIT pool state is not counted as a
live application handle and is retained until expiry or service exit.

Scope is one external virtio-net TCP-client backend under QEMU. No physical NIC,
UDP/DNS, listener/accept, local TCP, general client bindings, wait-set, or

independently qualified by the peer's FIN/ACK evidence. These limits remain
