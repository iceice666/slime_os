# PR scope classes, closeout automation, and author restatement

## Context

Every change today walks the same three pull requests — planning, implementation,
closeout — whether it changes the operating system or a CI workflow. The
planning-first rule exists because a stacked PR once mixed a new work item with
its implementation; the closeout PR exists because `just devloop complete` must
run against `origin/main` so a branch cannot grade itself. Both are enforced by
convention and review, not by a check, and neither distinguishes a product
change from a change to `.github/` or `CONTRIBUTING.md`, for which no `just`
recipe could grade an acceptance anyway.

Separately, the human author's role has drifted to approving agent-written
descriptions of agent-written changes. Nothing in the flow requires the author
to state, in their own words, what a change makes impossible; that statement is
the only step that binds the change to the author's understanding rather than
to the agent's.

## Scope

Three path classes, judged mechanically from the PR diff against its base:

- **product tree** — `slime-root/`, `components/`, `contracts/`,
  `boot-contracts/`, `sel4/`, and any other path a `just` recipe builds into an
  image;
- **grader closure** — `scripts/check/`, `scripts/lib/`, `just/`, `Justfile`,
  `.devloop/`;
- **everything else** — `.github/`, `CONTRIBUTING.md`, `AGENTS.md`, `docs/`,
  `.tasks/`, and other non-built, non-grading paths.

Rules over those classes:

1. **Planning PR scope.** A PR that adds a new `.tasks/items/*.md` file may not
   touch the product tree. It may touch the grader closure and everything
   else, because the exam lands with the item. CI refuses the mixed case.
2. **Process escape hatch.** A PR that touches neither the product tree nor the
   grader closure needs no landed work item. It still runs every applicable
   check, and its description states what it changes. This replaces the
   judgement call in the trivial-change exception for that class only; product
   and grader changes keep the landed-item requirement.
3. **Closeout automation.** A workflow on `main`, sibling to `myque-retire.yml`,
   finds spec-driven items that carry recorded gate evidence and are not yet
   `done`, runs `just devloop eligible` and then `just devloop complete` for
   each that passes, and proposes one `.tasks`-only PR. It never writes `main`
   directly and never fabricates evidence; an item that is not eligible is
   reported, not closed. A human merges the PR.
4. **Author restatement.** `AGENTS.md` gains one rule: before an agent requests
   merge of an implementation PR, it asks the author to write, unassisted, what
   the change makes impossible or newly possible; the agent does not draft that
   text, checks it against the diff, and reports any disagreement. The
   statement lands in the PR description. This is a behavioural rule for
   agents, not a CI check.

The classifier for rules 1 and 2 lives beside the existing diff-scope step in
`.github/workflows/ci.yml`, or in one small script under `scripts/check/` that
the workflow calls with a base and head revision; it is not a new `just`
target and does not enter `just tasks_check`, which stays offline over the
store alone. `CONTRIBUTING.md` documents the three classes and the rules;
`docs/getting-started/06-work-item-lifecycle.md` documents the automated
closeout.

Out of scope: changing what `just devloop complete` verifies, allowing
completion from an implementation branch, automatic merge of any PR, and any
change to the spec-driven mandate or the backlog-first rule.

## Exit conditions

- On a PR that adds a work item and also changes a product-tree path, CI fails
  with a message naming both; on a PR that adds a work item and changes only
  grader-closure or other paths, the same check passes.
- On a PR touching only `.github/` and `CONTRIBUTING.md`, no landed item is
  required by the documented rules, and the check that would demand one does
  not fire.
- The closeout workflow, run from `main` against at least one spec-driven item
  with recorded evidence, opens a PR containing only that item's `.tasks`
  transition; run against a tree with no eligible item, it opens nothing and
  says so.
- `AGENTS.md` carries the restatement rule, and at least one implementation PR
  after this lands carries an author-written restatement that the agent checked.
- `just tasks_check`, `just docs_check`, `just ruff`, and `just typos` pass.

## Verification

The scope classifier is exercised in CI on this item's own implementation PR
and on a deliberately mixed control branch that is not merged. The closeout
workflow is exercised by `workflow_dispatch` in preview mode before publication
is enabled, as `myque-retire.yml` was.
