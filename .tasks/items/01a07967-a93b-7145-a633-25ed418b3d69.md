# Finish the work-item store hard cutover

## Context

MQ1 moved identity into `.tasks/items/` and MQ2 turned `roadmap/00-backlog.md`
into an index over it, but both landed with a compatibility layer intact: 288
devlog entries still carried `Roadmap` front matter and roadmap ids,
`.tasks/legacy-roadmap-ids.json` resolved those ids, `scripts/lib/work_items.py`
was a resolver over that map with an ambiguity path for the twice-allocated
`B29`/`B30`, `check-work-items.py` carried migration-only policy, and
`scripts/migrate-roadmap-to-myque.py` plus `scripts/lib/roadmap_inventory.py`
could still reconstruct the store from roadmap headings.

That last point is the reason this is a defect and not tidiness: while a
roadmap-to-store path exists, `roadmap/` remains a latent second authority. The
documentation also still contradicted the model — `AGENTS.md` said roadmap
completion stays authoritative, `roadmap/00-backlog.md` instructed the reader to
add a heading when closing an item, and `roadmap/README.md` mirrored exact
aggregate counts that had already drifted (it claimed 218 done against an actual
219).

## Exit conditions

No runtime or check-time dependency on the pre-MyQue identifier system remains;
UUID is the only persistent work-item reference; keys are display aliases only;
`roadmap/` carries no state, identity, or dependency authority; and no mechanism
turns a roadmap edit into a store change.

## Exit condition (observed)

Closed 2026-09-07. All 288 `Roadmap` front matters were rewritten to `Work
items` UUID rows and `just devlog_check` passes at `291 entries, 291 indexed`;
`.tasks/legacy-roadmap-ids.json`, `scripts/migrate-roadmap-to-myque.py`, and
`scripts/lib/roadmap_inventory.py` are deleted (1136 lines) with `just
tasks_check` passing at `274 items, 94 frozen backlog headings indexed`.
`just ruff` and `just typos` pass. Closure identity is unaffected — no declared
release input changed and `generate-system-image-closures.py --check` reports
all 50 closures current. A repository-wide sweep left roadmap ids as historical
prose only: no active doc, checker, workflow instruction, or present-tense
source comment routes a reader to `roadmap/` for identity, state, or a live
defect's problem statement.

Review found the first round's checker acceptance boundaries wrong in three
places, each reproduced before being fixed and re-observed after:

- The frozen index required an indexed item to stay `done`/`cancelled`, letting
  a historical document veto a state transition in the canonical store. Removed.
  A reopened indexed item now passes `tasks_check` outright, and fails only via
  `check_backlog_first()` while a milestone is active — observed both ways.
- Anchor protection was claimed but absent: `check-devlog.py` stripped
  `#fragment`, and the heading guard's `headings == len(seen)` was satisfied by
  `0 == 0` after deleting every entry. Fragments are now validated against real
  headings and explicit `<a id>` anchors, and the landed heading set has a floor.
  Auditing all 77 devlog fragment links found 4 broken since they were written;
  restored with retained anchors rather than editing frozen bodies.
- Front matter was not an exact field set: a trailing `Roadmap` row passed, and
  a trailing duplicate `Work items | none` passed *while silently overriding the
  real UUID*. Rows are now parsed in order, duplicates rejected, and the field
  list must equal the declared eight.

A second review found two more, also reproduced first:

- The backlog index still collected resolved `B<N>` keys into a set, so with
  two `B29` sections the first one's UUID marked the second verified — the same
  non-unique-key merge the migration existed to remove. Sections are now
  validated by position, and the failure names the ordinal: stripping either
  duplicate's `**Item:**` line now fails, where both previously passed.
- The anchor scanner accepted headings inside fenced examples, had no duplicate
  `-1`/`-2` suffixes, and stripped the underscores out of inline code. All three
  reproduced, and the repository has latent exposure to two of them: 37
  inline-code headings carry underscores and 39 slugs repeat. The computation
  moved to `scripts/lib/markdown_anchors.py` with 11 executable controls that
  `devlog_check` runs before trusting it, and its docstring now declares what is
  out of scope instead of claiming GitHub fidelity. Two of those controls caught
  bugs in the module's own first draft.
