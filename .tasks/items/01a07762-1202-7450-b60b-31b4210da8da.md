# Backlog becomes an index over the work-item store

## Context

The MyQue migration moved identity into `.tasks/items/` but left
`roadmap/00-backlog.md` carrying all 94 resolved entries in full, so every
problem statement, exit condition, and status existed twice with nothing
holding the copies together. 95% of that file's 107655 bytes was state the
store already owned.

Deleting the file was not available: 75 devlog entries link into it and 8 of
those links are anchored at a specific `### B<N>` heading.

## Exit conditions

A sentence-level audit found the store a strict superset of the roadmap text
for 93 of 94 headings; the exception, `B29`'s second allocation, was the one
defect with no devlog entry, and its 2168-character body had been truncated to
570 by the migration. Its full investigation now lives in
`019fd7cd-8c00-782b-b8f9-66eb3350e63b`, making the store a superset for all 94.

The resolved log is now 94 headings, each with its devlog link and item UUID
and nothing else; the file is 27719 bytes. All 8 anchored devlog links resolve
against the surviving headings, and `just devlog_check` passes at 289 entries.

`check_backlog_index_resolves` in `scripts/check/check-work-items.py` fails
when a heading names an absent item, when a heading carries no `**Item:**`
line, when the file is missing, or when a heading under `## Resolved` names an
item that is not closed. All four arms were mutation-tested and observed to
fail with the offending key named.

## Verification

Gates: `just tasks_check`, `just devlog_check`, `just ruff`, `just typos`

## Notes

Also assigned keys `F1`–`F5` to the five deferred follow-ups, which the
migration left keyless and therefore indistinguishable in `myque list`, and
repaired two of their titles that the migration truncated mid-word.
`open_backlog` no longer counts `blocked` as blocking milestone work: a defect
