# Reduce final seL4 image size through ELF packaging and measured codegen

## Problem

Reduce final seL4 image bytes without reducing memory capacity, removing boot
checks, weakening ELF admission, or changing the capability model. The requested
scope is four optimizations: embedded component ELF stripping, measured root
codegen, embedded child ELF stripping, and unnecessary unwind metadata removal.

Earlier measurements used existing build outputs, not an identity-bound rebuild
of one revision. They identify candidates, not verified savings. A smaller ELF
file does not imply fewer mapped pages, less RAM, or fewer root CSlots: report
file bytes and loadable memory separately, including BSS, alignment and stacks.

## Scope

1. Strip non-runtime metadata from embedded component ELF delivery copies before
   generation encoding and signing. Preserve the original symbol-bearing build
   artifacts. Reuse the existing ELF tooling/admission path; retain entry points,
   required program headers, segment permissions, load bytes and zero-fill
   semantics. Cover workspace and external components without silently weakening
   input admission or changing the meaning of external source identities.
2. Measure root size-first codegen and supported LTO configurations against a
   rebuilt baseline. Compare the final packaged image, not just object files.
   Keep only configurations with observed size benefit and passing runtime gates.
   Scope changes to the intended build path; Cargo does not support LTO in a
   package-specific profile override. Do not impose unmeasured workspace-wide
   profile changes or assume size optimization always produces a smaller image.
3. Strip the embedded native child ELF delivery copy while retaining its symbols
   separately. Preserve all required fixture, fault, IPC and reclamation checks.
   Remove a fixture from a plane only if its actual control flow proves it unused;
   fixture removal is not an excuse to narrow existing verification.
4. Resolve actual panic, unwind, backtrace and target requirements before removing
   root unwind metadata. Prefer a build/link change over post-link corruption of
   program headers. A construction-failure path named unwind is not evidence of
   Rust stack unwinding. Demonstrate that supported boot and fault behavior remains
   intact; document any metadata that must remain and its measured cost.

## Boundaries

- Do not change descriptor capacities, allocator representation, CSpace limits,
  private-memory budgets, MEM-1G qualification or adaptive memory design.
- Do not strip the packaged loader ELF blindly: it carries sectionless payload
  segments. Kernel/root packaging and embedded component stripping are distinct.
- Do not promise a fixed KiB reduction before building comparable artifacts.
- Do not bless changed boot-layout fixtures solely because a check fails. Review
  the semantic change and preserve capability-slot contracts.
- Source changes require regenerated system-image closures and exact tested image
  identities. No physical-board qualification follows from QEMU execution.

## Exit conditions

- Capture before/after source revision, target, build settings, image identity and
  exact final bytes. Separately report generation bytes, root/child ELF file size,
  loadable file and memory extents, and removed symbol/unwind metadata. Do not add
  overlapping per-step savings or equate file-size savings with CSlot savings.
- Repeated equivalent builds produce identical delivery bytes. Stripped embedded
  ELF copies pass existing host/root admission; malformed inputs remain refused.
  Demonstrate preservation of the entry point, permissions, loadable bytes and
  zero-fill behavior, not merely that a stripping command exits successfully.
- Boot rebuilt root and product-component paths on AArch64, RV64 and x86-64 QEMU
  wherever the shared build changes apply. Exercise the child fixture and actual
  fault/reclamation paths. Run the existing fault-plane gate as well, but do not
  treat that alone as proof that an unwinder is unnecessary.
- Run `just contracts_check`, `just generation_check`,
  `just system_image_builder_check`, `just sel4_root_boot_check`,
  `just sel4_fault_check`, `just sel4_boot_layout_check`, and
  `just x86_64_sel4_root_boot_check`; use the existing root/component-graph
  checkers' platform arguments for RV64 and other affected product lanes.
- Run `just fmt_check_all` and `just lint_all` for permanent Rust changes, and
  `just ruff` for Python changes. Extend existing checks only for observable
  regressions; do not add a new top-level checker for this optimization alone.
- Update owning build documentation where procedures or symbol-artifact locations
  change. Record measured savings, selected/rejected codegen configurations,
  verification commands and retained limitations before closing this item.
