# Private-memory ledger refuses a legal successful-cleanup abort, leaving the transaction pending and wedging all adaptive growth

## Context

Found by the 2026-09-24 post-closure stress audit of MEM-ADAPTIVE (ledger
harness `build/mem-adaptive-stress2/ledger/`, `tests/repro.rs`
`f1_abort_table_bound_wedges_pending`; randomized state machine: 6714 refusals
of physically legal retention in 100k seeds x 200 steps).

`boot-contracts/src/private_memory_policy/ledger.rs` `Ledger::abort` with
`cleanup_succeeded` bounds retained leaf tables by
`old.pages + pending.pages`. Real tables are one per 2 MiB span touched, which
is not bounded by committed pages: `begin(513)` (large frame + table + page in
span 1) fails and aborts retaining 1 table (Ok); `begin(1)` in span 0 fails and
aborts retaining 1 table: `Err(Cleanup)`. The pending transaction then stays
`Some`: every later `begin` by any subject and the holder's `retire` return
`Transaction`. Root `settle_failure` returns `Policy(Cleanup)` and never falls
back to `abort(ZERO, false)`, so root cannot recover.

## Exit conditions

The retained-table bound admits every retention a real span layout can
produce, and root never leaves a transaction pending after any abort outcome.
Ledger host tests reproduce the sequence above and observe `Ok`; slime-root's
failure path is covered.

Gates: `just test_host`, `just test_sel4_root`, `just private_memory_phase4_check`
