# `launch_instance_graph` overflowed the root stack into mapped `.bss`

## Context

Resolved 2026-08-28. **Class:** Defect (latent memory corruption, masked by `.bss` layout).

`launch_instance_graph` subtracted 488 KiB from `sp` in one step for three stack locals — `TaskTable<48>`, `WindowTable`, and `LaunchedInstances` — against a 1 MiB stack, so every boot overflowed; whether that landed in mapped `.bss` slack (silent corruption, every gate green) or on `ScratchPage`'s guard page (an honest fault) depended only on where preceding statics placed `STACK`.

## Exit conditions

The three tables moved to `.bss` as `LAUNCH_TASKS`/`LAUNCH_WINDOWS`/`LAUNCH_INSTANCES`, the prologue fell to 0x51000, and all five IO planes plus `sel4_boot_check` and `sel4_capability_layout_check` passed.
