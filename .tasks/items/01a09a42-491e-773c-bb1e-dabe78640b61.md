# generation determinism check fails when TMPDIR lies under the repository root

## Context

`scripts/check/check-generation-determinism.py` builds generation 1 twice in two
`tempfile.TemporaryDirectory` trees and requires byte-identical `generation.bin`. Observed
2026-09-13 on `feat/pwm-servo` (IO8, also true of `main`'s inputs since nothing in the build
paths changed there): with `TMPDIR=/space/slime_os/build/tmp`, which the system-image closure
gates need because `/tmp` is a 7 GB tmpfs, the check fails with `two identical builds produced
different generation.bin bytes`; with the default `TMPDIR` the same tree passes at once. The two
temporary trees differ only in their names (`target-first`/`target-second` under the temp
directory); a temp directory below the repository root evidently lets that name reach a
component's bytes where one outside it does not, presumably through the path remapping the
builder applies relative to the root. Which component's bytes differ was not extracted.

## Exit conditions

Either the builder's remapping makes the two builds identical wherever the temporary directory
lies, observed by `just generation_check` passing with `TMPDIR` set below the repository root, or
the check refuses such a `TMPDIR` up front with a message naming the reason, so a builder does
not read a determinism failure as a product defect.

## Verification

Gates: `just generation_check` under both `TMPDIR` settings.

## Disposition

Deferred 2026-09-13 by decision: environmental, reproducible, and outside IO8's change; the
IO8 entry records its `generation_check` pass with the default `TMPDIR`. Reopen when picking
it up or if it reproduces with the default `TMPDIR`.
