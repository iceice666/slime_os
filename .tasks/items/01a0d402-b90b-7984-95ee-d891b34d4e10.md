# Adaptive guaranteed growth charges every leaf table to the guarantee, so a growth whose guarantee ends at a 2 MiB span boundary fails

## Context

Found by the 2026-09-24 post-closure stress audit of MEM-ADAPTIVE
(`01a09b65-4386-7b79-a64a-f263de037b8d`), on `feat/mem-adaptive-qualification`
at `e0c0b69`.

`slime-root/src/private_memory/elastic.rs` `grow` assigns `shape.tables` wholly
to the guaranteed half whenever `guaranteed_pages != 0`, and prices the pooled
half with `tables = 0`. The mapper (`slime-root/src/private_memory.rs`
`map_growth`) takes each table from the source of the page that needs it
(`GrowthPlan::source`), so a page past the guaranteed prefix that opens a new
span asks the common pool for a table the transaction never acquired.

Observed in a temporary host test (reverted): fresh region, redeemable guarantee
512, grow 513 on the base-page lane. `shape_in` gives `base_pages=513 tables=2`,
the pooled half `tables=0`, and `map_growth` returns
`Frames { allocated: 512, ArenaTooSmall { size_bits: 12 } }`. The whole growth
rolls back after `ledger.begin`. A component chooses its own delta, so it can
trigger this at will; the guaranteed half is also over-charged a table it
never uses.

## Exit conditions

A growth's leaf tables are divided by the page they serve: tables for spans
opened inside the guaranteed prefix are guaranteed, the rest are pooled, using
the same predicate the mapper uses. A slime-root host regression drives the
production `grow` with a ledger through a guarantee ending at a span boundary
and observes success, and the adaptive private-memory planes pass.

`just private_memory_adaptive_lifecycle_check`

## Closure evidence

Observed exit condition: slime-root host regression
`a_guarantee_ending_at_a_span_boundary_leaves_the_next_table_pooled` drives the

reverted. `grow` now splits tables with `Region::shape_split`, so the guaranteed
half owns only the tables its pages open.
