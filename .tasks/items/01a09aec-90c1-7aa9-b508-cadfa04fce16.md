# Contributor workflow and repository licensing policy

## Problem

Contributors need a concise route from GitHub intake to canonical work,
implementation review, and evidence-based completion. The repository also
needs an explicit multi-license policy that follows architectural ownership
instead of implying one license covers upstream kernel code, system software,
and public development interfaces.

## Scope

- Add `CONTRIBUTING.md`, summarizing the collaboration model and routing to
  `AGENTS.md`, existing PR templates, and the getting-started guides without
  duplicating their engineering or tutorial content.
- Add `LICENSE.md` and official, unmodified GPL-2.0-only, GPL-3.0-only, and
  Apache-2.0 texts under `LICENSES/`; add concise README license disclosure.
- Inventory ownership and architectural licensing roles in
  `components/runtime/`, `components/proto/`, `contracts/`, `boot-contracts/`,
  `scripts/`, and `sel4/`, including public SDK surfaces elsewhere. Explicitly
  classify public canonical schemas alongside their generated bindings.
- Require SPDX identifiers on new owned source files. Do not mass-add headers
  to existing mixed areas before classification. Add a narrow license gate or
  PR-link helper only if it reuses existing verification/tooling cleanly.

## Planning and relationships

This proposal is the work-item bootstrap exception: its PR changes only this
item. Merge the planning PR into canonical `main` before opening a separate
implementation PR. Do not stack implementation on the unmerged planning PR.
The implementation PR must link this UUID through `myque-gh pr link`.

No parent or dependency edges are required. This task documents the existing
MyQue and projector semantics; it does not change them or claim the projection
integration's remaining production evidence.

## Exit conditions

1. `CONTRIBUTING.md` exists and remains concise and contributor-oriented.
2. Human-created Issues are intake; reporters need neither MyQue nor `.tasks`
   edits. Accepted work is subsequently represented canonically.
3. Bot-created Issues with MyQue UUID and projection markers are projections.
   Title, body, state, `myque:*` labels, and parent/sub-issue relationships are
   projector-owned; human comments and ordinary labels remain human-owned.
4. `.tasks/items/<UUID>.md` is canonical; GitHub is collaboration, PRs are
   implementation artifacts, and devlog is evidence/history.
5. Non-trivial implementation requires an item already merged onto `main`
   through a distinct planning PR; the proposal itself is the bootstrap
   exception. Features, fixes, architecture, behavioral refactors, CI/gate
   semantics, protocols, drivers, hardware, authority, and substantial policy
   or documentation changes are explicitly covered.
6. Stacking implementation on unmerged planning is explicitly prohibited.
7. Implementation PRs use existing templates, identify canonical work, and
   machine-link UUIDs through `myque-gh pr link`; the human Related section
   alone is insufficient and managed trailers must not be hand-edited.
8. GitHub auto-close keywords are prohibited against managed projections.
9. `PR merged != work item done` is explicit: observe and record the actual
   exit conditions, then use `myque close` and commit the canonical transition;
   the projector subsequently closes the Issue.
10. README, getting-started, AGENTS, devlog, work-item, and PR ownership remains
    distinct. Link orientation, build/run, first-change, and add-component
    guides. Trivial exceptions are semantic, not based on line count.
11. `LICENSE.md` documents multi-license ownership and a concrete path/role
    inventory, including an explicit decision for each public schema family.
12. `LICENSES/GPL-2.0-only.txt` is the official unmodified license text.
13. `LICENSES/GPL-3.0-only.txt` is the official unmodified license text.
14. `LICENSES/Apache-2.0.txt` is the official unmodified license text.
15. Actual seL4 kernel-derived code remains GPL-2.0-only; seL4 userspace and
    build configuration are not classified as kernel merely by directory.
16. Owned system software above the kernel defaults to GPL-3.0-only.
17. Explicitly identified public ABI/SDK bindings use Apache-2.0, with public
    authoritative schemas classified consistently rather than blanket-
    relicensing all contracts or mixed directories.
18. Third-party, submodule, vendored, and upstream-licensed generated material
    retains its applicable upstream license and notices.
19. New owned source files require explicit SPDX classification by role, not
    extension. Contributions use the area's license; contributors retain
    copyright, with no new CLA or copyright assignment.
20. GPL-2.0-only kernel code must not absorb GPL-3.0-only implementation or
    Apache-2.0 SDK code without the required licensing review. Cross-boundary
    PRs preserve per-file licenses rather than collapsing domains.
21. README accurately describes the repository as multi-license and links
    `LICENSE.md` and `LICENSES/`.
22. Relevant task, documentation, and any introduced license checks pass;
    the implementation devlog records the inventory rationale, official text
    provenance, observed verification, and planning-main/PR-link evidence.

## Non-goals

No runtime behavior, MyQue schema, or myque-gh semantics changes. Do not
rewrite `AGENTS.md`, relicense upstream code, blanket-license `deps/`, all
contracts, or all `sel4/`, dual-license system software, or introduce a CLA.
Issue intake forms and a new SPDX gate are optional, not reasons to widen the
required deliverable or add heavyweight dependencies.
