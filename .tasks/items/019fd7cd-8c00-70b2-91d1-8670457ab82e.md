# `ChannelTable` never reclaimed, so `MAX_CHANNELS` was a lifetime bound

## Context

Resolved 2026-08-07.

B16's exact defect shape in a second table — `channel.rs` derived keys from a monotonic length and never freed an entry on task death, so `MAX_CHANNELS` bounded the channels a boot could ever mint rather than those live at once, and the downstream symptom (a refused mint) read as broken components rather than one exhausted table.

## Exit conditions

`channel::sweep` frees every entry no live holder can name, checked against both the live graph and in-flight `Transit` state (since a transfer drops the sender's entry before parking it), paired with a monotonic `next_key` so a freed slot's key is never reissued to a still-live capability; `just sel4_crossing_check` mints 33 pairs against a 32-entry table and still sends/receives on every live channel including one parked mid-transfer, with three targeted fault injections confirmed failing.

## Verification

Gates: `just sel4_crossing_check`
