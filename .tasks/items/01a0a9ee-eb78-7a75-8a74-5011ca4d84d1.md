# Document the work-item and spec-driven lifecycles in one place

## Problem

A contributor now has two ways to carry work: an ordinary item whose completion
is a recorded human observation, and a spec-driven item whose completion is
enforced against evidence bound to the exact tested inputs. Both share one
identity and storage model, including retirement to a terminal record and
verified reopening.

That whole path is currently readable only by assembling three documents.
`AGENTS.md` states the rules and the ownership split, `CONTRIBUTING.md` states
the contributor workflow, and `docs/decisions/spec-driven-work-item-bodies.md`
states what this repository owns versus defers. None of them is a route a
person can follow command by command, and `docs/getting-started/` — which owns
exactly that kind of route — says nothing about either lifecycle.

## Scope

- Add one `docs/getting-started/` page that walks both lifecycles end to end
  with copyable commands: propose, land planning, start, implement, record
  evidence, complete, retire, reopen.
- State at each step which program owns the decision: MyQue for identity,
  state, graph and storage; devloop for the requirements body, helper
  semantics and evidence; this repository for the body convention, gate policy
  and approval rules.
- Name what `just tasks_check` validates at each point, including that its
  summary counts only active spec-driven items, so an uncovered run reads
  `0 validated through devloop` rather than looking green.
- Record the boundaries a reader will otherwise trip over: approval refuses an
  item that is not yet on `main`; evidence is invalidated by changed
  requirements, helpers, code, policy, execution inputs, target, image or run
  epoch; the newest entry for an obligation decides it; a human obligation
  stays pending until an operator observes it; a direct `myque close` bypasses
  the eligibility boundary; `refs/myque/retained/*` needs an explicit refspec.
- Index the page in `docs/README.md` and route to it from `AGENTS.md` and
  `CONTRIBUTING.md` instead of repeating it there.

## Non-goals

Restating MyQue's envelope or devloop's schemas, which are owned upstream and
pinned; duplicating the decision record's rationale; changing any rule, gate,
policy or command; adding a checker.

## Planning and relationships

Work-item-only planning proposal. Merge it into canonical `main` before the
documentation PR, which must link this UUID through `myque-gh pr link`. No
parent or dependency edges are required.

## Exit conditions

1. One `docs/getting-started/` page documents both lifecycles end to end, with
   every command copyable and every owner named, and `docs/README.md` indexes
   it in sequence.
2. `AGENTS.md` and `CONTRIBUTING.md` route to that page rather than growing a
   second copy of the walkthrough.
3. Every command and path the page names resolves: `just docs_check` passes,
   which validates local links, fragments, canonical UUID references and
   current `just` recipe names.
4. The documented boundaries match observed behavior, including the refusals
   and the limits listed in scope. No claim is added that this repository has
   not observed.
