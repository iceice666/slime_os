# Private-memory ledger API: quarantine during a pending transaction is cleared by abort, and a witness can redeem table bytes as guarantee pages

## Context

Found by the 2026-09-24 post-closure stress audit of MEM-ADAPTIVE (ledger
harness `build/mem-adaptive-stress2/ledger/`, `tests/repro.rs` f2 and f3).
Neither is reachable from root today: root never calls `Ledger::quarantine`,
and root's witness counts payload pages only.

- `Ledger::quarantine` does not check `pending`; a later `abort(.., true)` sets
  `quarantined = !cleanup_succeeded` and clears it, and `commit` never checks
  quarantine.
- `Plan::validate_reserved` / `validate_runs` only require
  `guarantee_pages * PAGE <= witness.guaranteed.bytes`, and those bytes include
  guaranteed leaf tables, so a witness can record more redeemed pages than
  guaranteed payload.

## Exit conditions

Quarantine is sticky across a pending transaction and blocks commit, and a
witness's pages are bounded by guaranteed payload bytes; ledger host tests
cover both.
