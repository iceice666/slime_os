# network-service state machine runs on the host

## Context

`network-service`'s decision logic (`dispatch`, `serve_data`, `settle_connect`,
`release_capability`, `reap_drained`, `mint`, `accept_delegation`) runs over five parallel
structures (`capabilities`, `socket_slots`, `draining`, the smoltcp `SocketSet`, and the
static socket buffers) threaded through eleven-argument signatures, and the crate has no
host test: every lifecycle change is proved by a closure regeneration and a QEMU boot. Three
review rounds of PR #32 each found a misbehaving-client lifecycle gap the plane never
exercises. Raised by the maintainability review of PR #32 (IO11), 2026-09-12.

## Exit conditions

The pure decision logic lives in `components/lib` (`network_sockets.rs`: a `SocketPool`
owning the "a draining slot is still occupied" invariant behind a `SocketDriver` trait;
`network_core.rs`: the capability table, delegation admission, data-request validation and
the pending table, connect settlement, shutdown) with smoltcp implementing the trait inside
the service crate (`stack.rs`), completions returned as values and sent by `main.rs`, and
host tests under `just test_host` covering the lifecycle gaps the review rounds found. No
behaviour change: every marker and counter `just io_network_check` and `just io_tcp_check`
pin stays byte-identical.

## Verification

Gates: `just test_host` (the new lib tests), `just io_network_check`, `just io_tcp_check`,
`just lint_all`, `just machete`, `just system_image_closure_check`.
