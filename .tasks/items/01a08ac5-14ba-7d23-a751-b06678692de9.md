# Bounded serial transmit and a clock-paced heartbeat producer

## Context

The IO substrate has no way for a component to transmit on a serial port: `AuthorityInventory`
is populated only by a virtio-mmio probe, and the root's UART adapter reads a byte for the
console rather than writing one. A component also cannot pace itself in real time, because
`monotonic_read` returns raw timer ticks and no syscall reports their rate.

This milestone is a board-neutral MAVLink facility: two contracts, a 16550 transmit
driver, a producer that paces itself off the clock authority, one composition, and the one
syscall the cadence needs. It names no SoC, no pin, and no clock rate, and it is the second
consumer of the declared-device mechanism `IO8` introduces.

## Exit conditions

Under QEMU: the `sel4-mavlink` composition admits; the driver binds no device and stays resident
answering the protocol's no-device status; the heartbeat producer holds its 1 Hz cadence and
reports each refused send; graph health stays green; and the plane's boot layout matches its
frozen fixture. On the host: the generated Rust encoder and the checkers' Python decoder
reproduce the same pinned frame vectors byte for byte, and the new clock syscall is covered by
root unit tests.

Host tests and a QEMU plane do not establish anything about a physical UART..

## Closure

Closed on the observed exit, re-verified on `main` at `6168c05` with IO8.
`just sel4_mavlink_graph_check` encoded and decoded the contract's three pinned
frames before booting, then built the `sel4-mavlink` closure and booted it under
the pinned qemu-arm-virt profile: init launched the serial driver and the
heartbeat producer before Slisp, the driver bound no device and stayed resident,
the producer sent five heartbeats on a 62 500 000-tick deadline grid — lateness
per beat 8 750, 96 500, 111 500, 69 000, and 137 000 ticks, each bounded and
never shifting the grid — each refused `no-device`, sysinfo still launched, and
all six required resident instances remained live.

The plain and `sel4-pwm` arms passed unchanged, `just sel4_boot_layout_check`
matched every plane layout including `sel4-mavlink`, and
`just sel4_gate_control_check` still rejected every mutated transcript with the
product-graph marker pin raised to cover both new arms.

On the host, `just test_sel4_root` is 288/288 and `just test_host` passes with
the `serial_device`, `mavlink_heartbeat`, and `uart16550` cases; the Rust and
Python encoders reproduce the same pinned frames. The clock rate syscall the
Context calls missing, `clock RATE_READ`, was already in the tree with its root
unit tests, so no root change was needed.

The line behind the driver is a platform's, supplied in
`components/services/uart16550-driver/src/line.rs`; this tree carries none, so
no byte reaches a wire anywhere in this change. A QEMU plane and host tests
establish nothing about a physical UART.
