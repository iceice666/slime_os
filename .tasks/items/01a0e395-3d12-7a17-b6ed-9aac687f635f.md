# BootState lives at two partition layouts: selector reads LBA 0-1, manager and probes use LBA 1024-1025

## Context

Two BootState layouts coexist and no plane boots one against the other:

- `slime-root/src/boot_selector.rs` reads the redundant slots at partition-relative LBA 0 and 1 (`STATE_SLOT_A = 0`, `STATE_SLOT_B = 1`) beneath a boot-store directory (`contracts/bootstate/v1` boot-store offsets);
- `components/services/sel4-generation-manager/src/main.rs` and the rollback, recovery, and transfer probes under `components/testkit/` read and write the slots at partition-relative LBA 1024 and 1025 within the store partition `gpt::validate_store_partition` admits, and `check-sel4-rollback-plane.py` re-reads the image at those sectors.

`sel4_boot_selection_check` builds its own disk for the selector; `sel4_generation_check`, `sel4_rollback_check`, `sel4_recovery_plane_check`, and `sel4_transfer_check` build theirs for the userspace side. A disk the manager stages on is therefore not one the selector would select from, so the userspace management path and the pre-admission selection path are qualified separately and never as one storage layout.

Recorded while writing docs/architecture/generation-management.md, which states the split as a current limit.

## Exit condition

Either one partition layout is declared in a contract and both the selector and the userspace components read it (with a plane that stages through the manager and selects through the selector on the same disk), or a decision record states why the two layouts are intentionally distinct and the architecture page cites it. Observed evidence, not a documentation change alone, closes the first option.
