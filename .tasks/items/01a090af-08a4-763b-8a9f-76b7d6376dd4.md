# Verification gates evaluate every system spec serially; parallelize the zutai passes and cache them by input

## Context

Measured on 2026-09-11 on a 16-core host while landing IO11: one `zutai run` of
`contracts/system-spec/v1/check.zt` over one system spec takes about 9 s, and every gate that
needs the derived compositions runs it over all 43 specs, single-threaded and from scratch.
Observed wall times: `generate-system-image-closures.py` 8.5 min, `system_spec_check` 21 min,
`system_image_closure_check` 25 min, `system_image_builder_check` 63 min (its own pass plus
the dependency's), `contracts_check` 7 to 25 min. A QEMU plane boots and completes in one to
two seconds; the build's identity checks, which are what make a stale input refuse to boot,
are correct and are not the cost. Every one-line component change costs a regeneration pass
before its plane can boot again.

## Scope

- run the per-spec zutai evaluations in parallel: they are independent per spec, so the pass
  should take one evaluation's time on this host, not 43 of them;
- cache each spec's evaluation by the hash of its inputs (the spec, the checker, the stdlib),
  so an unchanged spec is not re-evaluated by every gate in one batch;
- let a gate that a `just` recipe depends on run once per batch rather than once per
  dependent recipe.

## Exit conditions

`just system_spec_check` and the closure generator each complete in under two minutes on a
16-core host with no spec changed, with byte-identical outputs to the serial path, and the
identity refusals still fire on a stale input.

## Verification

Gates: `just system_spec_check`, `just system_image_closure_check`, `just contracts_check`

## Observed exit condition

Closed 2026-09-11 on `perf/zutai-parallel` (worktree `/space/slime_os-zutai`), record in
`devlog/2026-09-11-zutai-gate-cache/`. Measured with `SLIME_ZUTAI_JOBS=2` while another
session ran the serial generators on the same 16-core, 14 GB host:

- `check-system-spec.py`: 664 s serial, 518 s cold, 3.1 s warm.
- `generate-generation-from-spec.py --check`: 512 s serial, 1.7 s warm after the checker.
- `generate-system-image-closures.py --check`: 598 s serial, 316 s cold, 7.7 s warm.
- `just system_spec_check` warm: rc 0 in 190 s end to end, almost all of it the unchanged
  `contracts_check` prefix, so the two-minute bound holds for the recipe's own scripts and
  not for the recipe.
- Byte identity: sha256 of every routed zutai stdout over all corpora (224 rows) identical
  across serial, cold, and warm; every `--check` generator leaves `contracts/` unmodified.
- Refusals with a warm cache: a `bootAttempts` edit is reported stale by the generator,
  as a diverging field by the checker, and as `identity mismatch` by the closure check;
  a malformed input is refused twice with no cache entry written.

Caching does not restructure the recipe chain; that and the 22 serial negative arms remain
follow-ups noted in the devlog entry.
