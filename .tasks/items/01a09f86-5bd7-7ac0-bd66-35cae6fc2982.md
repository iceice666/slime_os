# Archive development history before product cutover

## Problem

Historical records cannot be deleted safely until an independent archive is
complete, restorable, permission-appropriate, and byte-verifiable. The product
also has real machine consumers of historical paths, so file removal, link and
checker changes, fixture relocation, and CI changes must be one atomic cutover.

## Scope

### Archive gate

- After H2 is merged, refresh the inventory and choose a landed pre-deletion
  `main` commit as the archive anchor. Record its full commit and tree IDs.
- Preserve a complete Git snapshot and reachable history without rewriting
  source commits. Retain original paths and enough surrounding product tree for
  relative historical links to be understood. Inventory submodule objects, LFS
  objects, external attachments, and referenced commits separately; name every
  unavailable object rather than inventing a mapping.
- In an independent checkout, verify the anchor commit/tree, every file proposed
  for removal, evidence bytes and digests, representative relative/fragment
  links, restoration instructions, and repository permissions. Preserve
  pre-existing unresolved links as explicit findings; fix only migration-created
  breakage.
- Scan transcripts/captures for credentials and privacy exposure before any
  publication. Preserve or tighten access; copied product CI, release,
  projection, and task-sync automation must not execute in the history repo.
- Keep an independent restorable backup. Report archive construction,
  publication, and remote protection as distinct facts.
- If no authorized remote/retention location exists, create and verify a local
  bundle plus restoration instructions, mark publication blocked, and do not
  remove originals from the product repository.

### Atomic product cutover

- Remove only material classified and archived after H2. In the same change,
  update every active link, work-item locator, checker, recipe, and Woodpecker
  invocation that consumes it. Historical locators use repository identity,
  full commit, and original path, never mutable `main` or developer-local paths.
- Keep `.tasks/items/` as the only live state store. Locator changes must not
  rewrite historical outcome, exit evidence, state, hierarchy, or dependencies.
- Replace [`check-devlog.py`](https://git.justaslime.dev/iceice666/slime_os-history/src/commit/45ed1745907b2d0a13fdf70c8b34eb635bed5f23/scripts/check/check-devlog.py)'s all-history validation with focused current local
  documentation checks for links/fragments, canonical UUIDs, and current command
  references, reusing the existing anchor and Justfile helpers where practical.
  The legacy corpus remains checkable at the archived revision; do not edit old
  entries merely to satisfy today's commands.
- Remove only the frozen backlog-index dependency from `check-work-items.py`.
  Preserve `myque check`, canonical UUID/relationship integrity, dependencies,
  and backlog-first ordering with negative controls even when
  [`roadmap/00-backlog.md`](https://git.justaslime.dev/iceice666/slime_os-history/src/commit/45ed1745907b2d0a13fdf70c8b34eb635bed5f23/roadmap/00-backlog.md) is absent.
- Relocate the exact P3.E Duo transcript consumed by
  `check-duo-gate-control.py` into an owning product evidence/fixture path before
  deleting its devlog directory; preserve and verify its bytes.
- Change `check-component-sdk-export.py` to use a stable non-exported current
  product file for its negative control rather than [`devlog/README.md`](https://git.justaslime.dev/iceice666/slime_os-history/src/commit/45ed1745907b2d0a13fdf70c8b34eb635bed5f23/devlog/README.md).
- Retain `evidence/framework-cpu-boot/` unchanged as current qualification input.
  Do not move, rewrite, restamp, or re-bless the recorded observation.
- General docs checks must run without a history checkout and without network
  access. The history repository must never become a product submodule or build
  dependency.

## Exit conditions

1. The archive restores the named commit/tree independently and every removed
   file's bytes match an archive manifest or Git object.
2. Missing required archive files, a digest mismatch, or an unavailable archive
   blocks product deletion.
3. No new unresolved active link, fragment, UUID, command, checker fixture, CI,
   or work-item locator points at removed product paths.
4. General product builds, host tests, docs checks, and work-item checks run with
   no history checkout and make no history-network request.
5. `just tasks_check` continues to reject malformed stores, invalid dependency
   relationships, and active milestone work ahead of open backlog defects while
   succeeding without the frozen backlog index.
6. Current docs checking accepts an ordinary change with no devlog and rejects
   invalid active local paths, fragments, UUIDs, and Justfile command references.
7. `duo_gate_control_check` consumes byte-identical relocated evidence and keeps
   its missing/reordered/failure mutation refusals.
8. Framework evidence controls continue to reject missing, forged, mismatched,
   or unbound observations; no new physical pass is produced.
9. Product runtime, ABI, contracts, pins, image identities, task semantics, and
   hardware claims are unchanged.
10. A product `docs/history.md` may identify the archive, fixed anchor, lookup
    method, evidence split, and future investigation policy, but contains no
    duplicate chronological index.

## Non-goals

Do not force-push, rewrite source history, publish without authorization, create
an artifact service, move current checker inputs merely because they once lived
under [`devlog/`](https://git.justaslime.dev/iceice666/slime_os-history/src/commit/45ed1745907b2d0a13fdf70c8b34eb635bed5f23/devlog/), make external-host availability a product test result, or treat
an archive as proof that a historical or current qualification passed.
