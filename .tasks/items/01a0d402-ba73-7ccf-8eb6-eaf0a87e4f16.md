# Root census counts an extent adopted for infrastructure in both infrastructure_owned and active_extent_bytes

## Context

Found by the 2026-09-24 post-closure stress audit of MEM-ADAPTIVE (allocator
harness `build/mem-adaptive-stress2/allocator/`, `harness.diff`,
`adopt-census.log`).

`extent_buddy.rs` `adopt_returned_extent` adds the extent to
`Infrastructure::owned_bytes` and also `assign`s the record active, so
`ObjectAllocator::active_extent_bytes` sums it too. Host harness: split a 2 MiB
extent, adopt one 1 MiB child: reusable+active+infrastructure goes from 2097152
to 3145728. Existing transcript `build/sel4-private-memory-matrix-mem1024.log`:
the census byte sum jumps by exactly the 5701632 adopted bytes between
`retired=4` and `retired=5`, and `active_extent_bytes` stays 5701632 once every
task has retired. `check_capacity_conservation` does not run on any plane that
adopts.

## Exit conditions

Adopted bytes appear in exactly one census category, and a plane that adopts
extents runs the capacity-conservation check and passes.

Gates: `just test_sel4_root`, `just private_memory_matrix_check`
