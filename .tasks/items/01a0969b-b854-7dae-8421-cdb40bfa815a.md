# the builder relates declared socketLimit sums to network-service socket capacity

## Context

`network-service` carries four TCP sockets (`TCP_SOCKETS`) and eight capabilities
(`MAX_CAPABILITIES`), shared by every client, while `socketLimit` is declared per holder and
destination in the system spec and the builder relates neither. A spec that raises a
`socketLimit` above the service's capacity is admitted and fails at runtime as `DENIED`; one
client cycling four connections parks every client behind the draining sockets' TIME-WAIT.
Raised by the maintainability review of PR #32 (IO11), 2026-09-12.

## Exit conditions

`scripts/build/generation_resources.py` refuses a spec whose sum of `socketLimit` over the
holders bound to the network service exceeds the service's declared capacity (a manifest
field the service reads, or the constant until then), and `check-system-spec.py` carries a
refusing case. Every existing composition still builds.

## Verification

Gates: `just contracts_check`, `just system_spec_check`, a negative fixture the spec checker
refuses.

## Disposition

Deferred 2026-09-12 by decision: it matters once a spec declares more than four sockets to
the service; land it with the second data client.
