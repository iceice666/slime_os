# sel4-replay plane: one gate run failed its ordered chain at the driver's startup authority marker under host load (no transcript kept)

## Context

While verifying B93 on 2026-09-11, one run of `just replay_check` failed with

    seL4 replay plane check: a holder of an unrecorded source carries no determinism
    claim: missing marker: \[virtio-blk-driver\] authority rings=1 rights=read,write
    source=generation

That marker is the second pattern of an ordered chain whose first is the root's
`SLIME_RECORD entry task=\d+ instance=replay-unrecorded …` staging line, so the failure
means the driver's startup line was not found after that root line, not that it was absent.
The checker keeps no transcript on failure. The run overlapped two zutai-bound gates that
saturated a core, which changes the guest's timer-driven interleaving. Eight transcripts
kept through the checker's own `boot()` before and after all satisfy its matcher, and the
gate passed on rerun. B93's change touches only the driver's shutdown reply and cannot move
its startup markers.

Record: `devlog/2026-09-11-b93-rollback-driver-fault/` (Open risks).

## Exit conditions

Either a transcript of a failing run shows which line moved and the chain or the
composition is corrected so the order is enforced rather than assumed, or twenty
consecutive `just replay_check` runs under load pass and the item is deferred again with
that evidence.
