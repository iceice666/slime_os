# Mixed-size private frames with exact growth semantics

## Context

Private growth currently maps only 4 KiB frames into a 2 MiB reserved window. Introduce 2 MiB frames as an internal mechanism before raising the public ceilings. The existing page-count ABI, quota units, stable base, and authority remain unchanged.

## Scope

- Extend `slime-root/src/object_allocator.rs`, `private_memory.rs`, and `child_vspace.rs` with architecture-qualified frame types, alignment-aware reservation, and lazy compatible page-table construction for AArch64 and RV64.
- Update `private_memory::arena_reservation` and its task-construction caller in this milestone to reserve large-frame alignment after image/kernel objects. This is the existing single-arena planner correction, not the successor's segmented-ownership redesign. Test that the reservation covers both bulk and incremental legal growth, including physical padding, before a task starts.
- Map aligned complete spans with 2 MiB frames and retain 4 KiB backing for small or unaligned growth. Do not install a leaf table where it would prevent a later block mapping; do not replace existing live mappings implicitly.
- Track actual object sizes, alignment padding, and page-table allocations through transactional failure unwind. Handle an unavailable aligned block explicitly without silently promising an unbudgeted small-page fallback.
- Keep the existing 2 MiB/task and 8 MiB aggregate contract ceilings. This milestone does not add live shrink, automatic page promotion, large shared buffers, or a new wire format.

## Exit conditions

- AArch64 and RV64 QEMU components each grow an aligned 512-page region, touch/read every 4 KiB subpage, and observe zero-fill before first write. The private data backing is exactly one 2 MiB frame, excluding separately reported page tables and other task objects.
- Assert the virtual block-alignment precondition explicitly: the current window base is aligned to its 2 MiB span. Later target-qualified window sizes must preserve at least 2 MiB base alignment and rerun this block-mapping case; a larger span is not a substitute for checking the mapping invariant.
- One-page and unaligned growth preserve exact 4 KiB accounting, the old extent and data, stable addressing, write access, and execute-never protection. Attempts to access another task's private memory or map shared buffers into the reserved window remain refused.
- Host cases cover small heads/tails, large-block boundaries, non-contiguous incremental requests, alignment loss, and insufficient aligned untyped space. Large mixed extents above the current public ceiling are internal planning cases only, not a runtime capacity claim.
- Injected retype and mapping failures leave the committed extent, quota, CSlots, and reusable backing as before the attempt, including any page tables and padding; normal exit and task fault reclaim every new object. Repeated failure/retry does not consume capacity.

## Verification

Gates to extend/run during implementation: `just private_memory_check`, `just test_sel4_root`, `just sel4_root_boot_check`, `just sel4_gate_control_check`, `just fmt_check_all`, `just lint_all`.

The current private-memory checker launches AArch64 only. Extend its existing mechanism to execute the same cases on RV64, using the shared seL4 runner where execution is shared; do not claim RV64 coverage from an ARM run or create a checker per milestone. Record the exact newly supported invocation and negative marker controls in the implementation devlog.
