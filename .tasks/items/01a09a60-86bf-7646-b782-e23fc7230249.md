# Integrate automatic GitHub projections with canonical MyQue state

## Context

Keep `.tasks/items/` authoritative and use the pinned `mozufu/myque-gh`
reusable workflow to reconcile selected items into GitHub Issues. GitHub PRs
are implementation artifacts linked by canonical UUID trailers, not a source
of work-item state. All unfinished states (`open`, `active`, `blocked`, and
`deferred`) are selected for first projection; existing trusted Issues and
required canonical parents remain managed, including terminal parents.

## Exit conditions

- `just tasks_check`, `just devlog_check`, and existing PR CI pass without
  changing the normal CI workflow, dev shell, or work-item schema.
- A committed-source `myque-gh plan` covers every unfinished item, existing
  trusted projection, and required parent, with no unexplained identity claims
  or unrelated terminal-item creates.
- After PR merge, Actions creates the first Issues as `github-actions[bot]`;
  titles, bodies, UUID markers, `myque:*` labels, states, canonical hyperlinks,
  and native parent/sub-issue relationships match the store.
- Reconcile is a no-op with stable inputs, repairs managed title/body/state
  drift with identity headers intact, and preserves human labels and comments.
- PR #32 is explicitly linked to IO11 by `myque-gh pr link`; the Issue shows
  its lifecycle, CI, and review observations after dispatch. No historical
  bulk linking is performed.
- A real linked PR merge is observed without an automatic canonical close.
  A genuinely completed canonical item is subsequently closed with `myque
  close`, and its Issue closes after that `.tasks` change merges to main.
  Do not fabricate completion or merge a PR merely to exercise this check.
- The devlog records production run URLs, source commits, Issue identities,
  and observed outcomes. This item stays unfinished until those observations
  exist; its implementation PR merging is not completion evidence.

## Verification

Pre-merge: `just tasks_check`, `just devlog_check`, workflow syntax validation,
and the pinned CLI's read-only plan against the exact committed source.
Post-merge: the production scenarios above, recorded in
[the integration devlog](../../devlog/2026-09-13-myque-github-projection/index.md).

Main `.tasks/**` and projector-workflow pushes, PR target lifecycle/body events,
managed Issue edits/state/labels, and completed `CI` runs trigger reconciliation.
Both successful and failed CI runs refresh native facts, including fork PR CI.
A twice-hourly schedule covers review changes, external checks, and events
suppressed for `GITHUB_TOKEN`; scheduled execution may be delayed by GitHub.
Manual dispatch is an operational escape hatch, not a contributor requirement.

Privileged events must use the pinned reusable workflow's explicit canonical
main checkout and pinned CLI only: never PR-head checkout/execution, artifacts,
or caches. Triggers observe GitHub facts but never mutate canonical state.
The query includes deferred work without activating it; parent closure does
not complete children or parents. Narrowing the query does not unmanage trusted
existing Issues. Disable the workflow to stop writes, and never delete identity
markers as rollback or infer completion from GitHub auto-close keywords.

## Observed production evidence

On 2026-09-13, the integration PR merged and Actions created exactly the
expected bot-owned projections. Canonical content, hyperlinks, labels, native
parents, PR facts, stable-input no-op, managed drift repair, and preservation
of human labels/comments were observed. The merged implementation PR did not
change this item's active state.

Observed runs and GitHub projection identities belong in the
[production qualification audit](../../devlog/2026-09-13-myque-production-qualification/index.md),
not in the canonical store as a mapping.

Still unobserved: genuine canonical completion followed by Issue closure after
a `.tasks` PR merges. IO11 and IO10 retain their own exit conditions. Do not
close this integration item merely because its implementation or evidence PR
merged.

## Expanded automatic projection acceptance

- The user's expanded policy is published by a normal reviewed PR: all four
  unfinished states, with terminal items added only as required parents or
  retained existing projections.
- Main workflow-only changes trigger apply as well as `.tasks` changes.
- Real PR body/lifecycle changes and CI completion refresh linked Issue facts
  without contributor dispatch; native review changes converge through the
  schedule without granting fork review workflows a write token.
- A managed Issue edit triggers canonical repair, preserving human data and
  avoiding a projector-generated event loop. Non-managed Issue activity and
  execution in fork repositories do not invoke the writer.
- Production records expanded create counts, canonical parent additions, event
  run URLs, and unchanged canonical completion authority. The original remaining
  genuine-close propagation condition still applies.
