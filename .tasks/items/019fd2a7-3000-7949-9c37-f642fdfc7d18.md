# the seL4 stream gate was scheduling-dependent

## Context

Resolved 2026-08-06.

`just sel4_stream_check` passed roughly one run in three, from two independent causes invisible on x86's cooperative scheduler: a publisher sending dead-code traffic on an already-finished route that later hit `ERR_PEER_DEAD`, and `debug_write` issuing one syscall per byte so unrelated printed lines could interleave mid-string and corrupt gate markers.

## Exit conditions

the dead-send is deleted, and `Operation::DebugWrite` is now served by the root's single-threaded graph loop so a printed line cannot interleave with anything; ten consecutive `sel4_stream_check` runs pass with all other affected gates unchanged; two plausible alternative fixes were tried and reverted because each broke a different invariant, and are recorded as such.

## Verification

Gates: `just sel4_stream_check`
