# Framework CPU-boot evidence unbound by the clean source baseline

## Context

Re-establishing the repository as a clean source baseline changed
`slime-root.elf`, so the Framework media image that P6.6's physical observation
was recorded against can no longer be rebuilt. `just framework_cpu_boot_check`
fails with `observation does not name the approved boot-media identity`.

Measured after the rebuild: the medium's `kernel.elf` is unchanged at
`1ae6fd038c8f24ba…`, still equal to the pinned pc99 `kernel_sha256`, while the
rebuilt media identity is `9a552d7350bbc633…` against the `104b5959704a69ed…`
named by `evidence/framework-cpu-boot/slime-cpu-boot.observation.json`. The
delta is entirely in the root, not the kernel.

The recorded boot is not retracted and its raw evidence stays frozen. It is now
evidence about a superseded image.

## Exit condition

An operator cold-boots the rebuilt Framework medium on the named machine and a
new observation record is written and validated, so
`just framework_cpu_boot_check` reports the claim again. No QEMU plane can close
this; `just framework_media_check` already passes and does not substitute.

The observation JSON must not be re-stamped to the new digests without that
boot, because doing so would assert a boot nobody performed.
