## Part C — technical design (smoltcp inside network-service)

### C1. Topology
- **(a) service ↔ driver:** the io-link-probe shape verbatim: service holds a `sharedBufferFactory` grant, creates 2 queue pages + 8 frame pages at `BASE = 0x19_0000_0000`, `format(bytes, 8, 1)` both queues, delegates 2 queue loans + 8 data loans over `network-service-link-peer`, waits for `b"ready"`, attaches `Queue` + `Outstanding<8>` per direction, resolves the five notification names. Driver unchanged.
- **(b) client ↔ service (bytes):** one IO0 queue per data client; request payload = `WireNetworkRequest` (56 B), completion payload = `WireNetworkCompletion` (24 B), bytes in the request's `WireBufferSlice`. Probe creates 1 queue page (8 slots) + 2 data pages, delegates the three loans over `network-probe-service`, signals `network-probe-request-ready` after each submit; service signals `network-probe-completion-ready` after each complete. Service maps loans at `BASE + 10*PAGE`.. and is the "driver half" (`take_request`/`complete`), answering every consumed request with a terminal status.
- **Op split:** endpoint carries OP_CONNECT/CLOSE/RESOLVE/LISTEN/ACCEPT (unchanged transport). Endpoint OP_SEND/OP_RECV run the full authority check then answer `STATUS_UNSUPPORTED` ("endpoint carries no slice"), so intruder assertions stay true for the authority reason. Data-queue OP_SEND: `slice.direction = DIRECTION_DEVICE_READ`; OP_RECV: `DIRECTION_DEVICE_WRITE`; fields `op`, `capability`, `flags` (0 or `FLAG_NONBLOCKING`), rest zero (already accepted by `valid_network_request`). Completion: `status_detail` 0/negative, `flags = FLAG_END_OF_STREAM` when FIN delivered and RX empty, IO0 `transferred` = bytes moved; IO0 status OK / BAD_RIGHTS (+detail −1) / BAD_SLICE (length > byteBudget or lease/page overrun or wrong direction) / MALFORMED / EXHAUSTED (pending ≥ queueDepth or unknown lease) / CANCELLED (settled by OP_CLOSE) / DEVICE_ERROR (+detail −4 reset by peer) / RESET (service shutdown). SEND retains the lease until all bytes are accepted by `send_slice`; RECV completes with ≥1 byte or EOS unless nonblocking. Pending table per client `[Option<PendingData>; 8]` keyed by IO0 request id.

### C2. smoltcp `Device` over LinkDevice (`network-service/src/link.rs`, pool in `components/lib/src/link_frames.rs`)
- `FramePool`: slots 0..4 RX-only, 4..8 TX-only (static partition so TX pressure never starves replenishment). States `RxProvisioned{request_id}`, `RxReady{len}`, `Free`, `TxRetained{request_id}`; transitions `provide`, `rx_complete`, `take_ready`, `release_rx`, `take_tx`, `tx_complete`. Zero-pad to `MIN_FRAME_BYTES = 60` (smoltcp emits 42 B ARP; the driver refuses < 60).
- `receive()` returns `(RxToken, TxToken)` only if a ready RX slot and a free TX slot exist; `RxToken::consume` reads the page then re-provisions with `OP_PROVIDE_RECEIVE`, `frame_len = 1518`, slice `{offset 0, length 4096, DEVICE_WRITE}`, signals `rx_request_ready`. `transmit()` = `Some(TxToken)` iff a TX slot is free (else backpressure). `TxToken::consume` writes the page, pads, submits `OP_TRANSMIT` with slice `{length frame_len, DEVICE_READ}`, signals `tx_request_ready`; slot stays retained until completion. `capabilities()`: `Medium::Ethernet`, `max_transmission_unit 1514`, `max_burst_size Some(4)`, software checksums (`features=0`, no offload).
- Completion drain (event loop): `take_completion` per direction; TRANSMIT → `tx_complete`; PROVIDE_RECEIVE OK → `rx_complete(id, reply.frame_len)`; RESET/DEVICE_ERROR → free + re-provision; `QueueError::Unknown` → count and continue. Startup: provide all 4 RX slots before `Interface::new`; `OP_QUERY_LINK` must report up.

### C3. Clock and event loop
- `Clock { base, ticks_per_ms = rate / 1000 }` from `CLOCK_RATE_READ` (62 500 on TCG virt); refuse `rate < 1000`; `now() = Instant::from_millis((ticks − base) / ticks_per_ms)`; pure conversion in `components/lib/src/tick_clock.rs`.
- Poll loop (no `timer_arm`): drain link completions → poll `state_changed` → serve control endpoints (non-blocking recv per client slot) → poll `probe_request_ready` → admit data requests → `iface.poll(now, &mut link, &mut sockets)` → service pending data → settle deferred connects → `yield_now()` if no progress; exit when all clients closed and no socket active. `poll_delay()` logged once as evidence timers are live. `Config::new(EthernetAddress(mac))` with `random_seed` from ticks.

### C4. Bounds and no-alloc
- No-alloc; storage as locals in `main`: `[SocketStorage::EMPTY; 4]`, RX/TX `[[u8; 4096]; 4]` each (32 KiB), `TCP_SOCKETS = 4`, `PENDING_PER_CLIENT = 8`, `RX_FRAMES = TX_FRAMES = 4`. Guard `SocketSet::add` with our own count (it panics when full). Ephemeral local ports from 49152, skipping held ports.
- Ceiling mapping: `socket_limit` enforced (today); `queue_depth` = max pending data requests per capability (EXHAUSTED beyond); `byte_budget` = max `slice.length` per request (BAD_SLICE beyond); `timer_budget`/`retry_limit`/`reconnect_limit` unenforced and reported as such in the authority marker.

### C5. Authority mapping
- OP_CONNECT: `find_destination(holder, Tcp, Ipv4(addr), port, Connect)` → socket_limit → DNS/UDP → UNSUPPORTED (after authority, so an unheld name still answers DENIED) → allocate socket (DENIED + `socket_refusals` when `TCP_SOCKETS` exhausted) → `socket.connect(iface.context(), (addr, port), local_port)` → mint capability, **defer reply** until ESTABLISHED.
- `CAPABILITY_TCP_CONNECTION` id = index into the 8-entry table now carrying `handle`, `destination`, `rights`, `pending`, `holder`, `epoch`. Data requests resolve id → entry → `sockets.get_mut::<tcp::Socket>(handle)`; holder = the queue owner.
- Refusal order on the data queue: decode/`valid_network_request` → capability unknown or wrong holder (BAD_RIGHTS, cross_holder) → epoch → SEND/RECV right (BAD_RIGHTS, rights_refusals) → direction / byte_budget / page overrun / lease not delegated by this client (BAD_SLICE) → pending ≥ queue_depth (EXHAUSTED). No byte touches a socket before every arm passes.
- Intruder (endpoint only, no queue): the eight existing denials; OP_CONNECT to the probe's tuple (holder mismatch) and to an undeclared address → DENIED; OP_SEND/RECV with ids 1..4 → DENIED; its own two rights-limited destinations connect with a real handshake (peer accept-only ports) then SEND-without-right / RECV-without-right → DENIED with the service marker proving zero bytes moved; OP_LISTEN → DENIED.

### C6. Address configuration and MAC
- `contracts/network-interface/v1` (Part B S1) is the source; the gate derives QEMU's `mac=` from the composition. DHCP out of scope. MAC-from-device (virtio config space via a new link op) deferred to the board lane; note in the contract comment.

### C7. Host tests
- `link_frames.rs` `#[cfg(test)]`: partition invariants, RX-ready ordering, padding to 60, unknown-id completion refused, TX exhaustion → `None`, RESET frees and re-provisions. `tick_clock.rs`: 62.5 MHz and 1 GHz, wraparound, `rate < 1000` refused. `components/proto/tests/network_service.rs`: data-plane request validity, EOS completion validity. `boot-contracts` tests for the interface decoder (mirror `network_destination.rs`).
- Optional smoltcp cross-wire test as a `dev-dependency` of `slime-components`: two `Interface`s over two `FramePool`-backed fake devices back-to-back (ARP + ICMP echo + TCP echo) on a fake clock; needs the Device impl generic over a small `Link` trait. If unwanted, keep tests to the pure pool.

### C8. Risks
- smoltcp panics under `panic = "abort"`: guard `SocketSet::add`, stale handles, non-unicast MAC/IP (builder validation + startup refusal); an internal assert is a component failure the plane reports, never a hang.
- RX starvation with 4 RX pages: bursts > 4 frames between polls are dropped by the device; markers report `stalled=`; fix = driver `DATA_LOANS` bump in the board lane.
- Client death while the service holds its loans: root settles loans (`reclaim_holder`); each iteration check endpoint liveness (`recv < 0`) **before** servicing pending data; drop that client's pending table without completing; `abort()` its sockets; never touch a reclaimed page. Driver death = `STATUS_PEER_DEAD` on the link rings → report and exit nonzero.
- Deferred OP_CONNECT vs the probe's blocking `call()`: `set_timeout(5 s)` bounds it; the gate's 240 s is the backstop.
- Page ceilings: service 10 + probe 3 + queues ≪ `MAX_TOTAL_PAGES 256`; declare `mappingCount = 13` for the service or `shared_buffer_loan_map` fails at startup.

Image size > 65536 → `imageSizes`. `link_peer.py` as oracle → keep `link_peer_check` + frame log. Test-run record for the shared checker will list `virtio-net-device` although the authority arm attaches none (state in the S1 devlog).
