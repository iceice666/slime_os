## Summary

Slisp now has a bounded freestanding C core and an interactive pure S-expression REPL. The externally admitted seL4 component reads its declared input capability, preserves top-level `define` bindings across forms, renders values or typed failures, and exits cleanly on Escape. The identical evaluator source passes 15 host behavior vectors plus a persistent-session vector before QEMU drives `(define answer 40)`, `(+ answer 2)`, and an arity refusal through the real console path.

## Changes

| Area | Change | Restored invariant |
|---|---|---|
| Reader | Added bounded parsing for integers, symbols, proper lists, whitespace, and nested forms over a fixed 192-node arena. | Every accepted program has an explicit structural bound; malformed or oversized input fails rather than allocating or truncating. |
| Evaluator | Added `quote`, `if`, `fn`, `let`, `do`, lexical closures, two-argument arithmetic, and equality over fixed binding and depth bounds. | Core language semantics are ordinary S-expressions with lexical scope; shell behavior does not require reader punctuation or implicit environment state. |
| Errors | Added distinct syntax, capacity, unbound-name, type, arity, and divide-by-zero results. | Structural and runtime failures remain distinguishable and deterministic. |
| Session | Added bounded persistent top-level state and `define`; each submitted form evaluates against the retained lexical environment. | Interactive definitions survive across forms without ambient process state or reader-specific assignment syntax. |
| REPL | Added input-capability acquisition, line buffering, value/error rendering, prompting, and explicit Escape termination to the C component. | Slisp is an actual interactive shell surface over declared authority rather than a boot-time self-test. |
| Build | Extended the freestanding C component builder to compile multiple translation units into one external ELF. | The language core and component entry remain separate C modules without a Cargo wrapper or source amalgamation. |
| Generation | Added the `slisp` boot action, external manifest, product image variant, and component specification generated by the gate. | The Slisp ELF is admitted by name, digest, target, and declared lifecycle before execution. |
| Verification | Extended `slisp_core_check` to compile host vectors, build the external ELF, script real key events, and require persistent-definition, evaluation, refusal, clean-exit, and healthy-graph markers. | Host semantics and the real console/input/component path guard the same implementation. |

## Decisions

- Decision: Start with one pure S-expression evaluator rather than compatibility syntax for shell pipelines, interpolation, or command substitution.
- Rationale: A single reader grammar keeps the language inspectable and makes process operations ordinary capability-bearing functions in later slices.
- Rejected alternative: Preserve Dango surface syntax and translate it to Lisp; that would retain the complexity the replacement is intended to remove.
- Decision: Use fixed arenas and explicit capacity errors in the bootstrap core.
- Rationale: The current component has no private-memory grant or allocator, and bounded state makes resource use an admitted property rather than a runtime hope.
- Rejected alternative: Add a heap grant before semantics require one; that expands mechanism and authority before the small core proves useful.
- Decision: Keep `nil` truthy and make only `false` select the false branch.
- Rationale: This follows a Scheme-like single-false-value rule while preserving `nil` as the empty-list value.
- Rejected alternative: Treat the empty list as false; that couples list representation to control flow and creates a second false value.

## Open risks and follow-ups

- [ ] Slisp cannot yet invoke spawn, stream, filesystem, or capability operations; those must be explicit generated C APIs and ordinary Lisp functions, not reader forms.
- [ ] Integer arithmetic currently follows C signed arithmetic; checked overflow semantics must be chosen before programs can depend on boundary behavior.
- [ ] Persistent definitions consume the fixed node/binding arenas monotonically; long sessions need bounded reclamation or a declared private-memory strategy.
