The root gate asserts `found=0` rather than tolerating it. Together the two
gates are what make the probe an observation: the same code must report nothing
when nothing is attached and name the disk when one is. Either alone is
satisfiable by a probe that returns a constant.

Values read, and where they come from:
- device=2   virtio device id for a block device
- vendor=0x554d4551  "QEMU" little-endian
- transport=0xa003e00  the highest of the platform's 32 declared transports;
  QEMU attaches downward from the top, so a single -device lands there
- irq=79  the DTB's `interrupts = <0x00 0x2f 0x01>` on virtio_mmio@a003e00:
  SPI 47, which seL4 numbers from 32. Derived from the transport address by
  the same arithmetic the device tree encodes, and only bound for a transport
  that is actually attached.
