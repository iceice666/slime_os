## Summary

CP12's derivation of `sel4-matrix` and `sel4-c-runtime` retired both compositions' recorded blockers, which turned out to be misdiagnosed: `sel4-matrix`'s was a component-spec authorization gap CP12 had already fixed, and `sel4-c-runtime`'s reason never actually prevented derivation. Migrating their gates exposed that the product-graph and device planes' recorded blocker — an uncommitted Slisp implementation — was also wrong: the closure model's `implementation_path()` simply had no case for an `external` provider. Committing the two product C ELFs it needed and fixing that gap unblocked `sel4`, `sel4-slisp`, and confirmed `sel4-c-runtime`'s `undeclared` provider correctly refuses one. The first closure build of the product graph then silently dropped `SLIME_QEMU_KEYBOARD`, because the legacy variant set it unconditionally rather than as declared root data; the plane's interactive shell markers went missing until it became a `qemuKeyboard` closure parameter. With 44 of 49 gates migrated, 39 of 40 surviving plane flags in `build-sel4.py` became unreachable and were deleted along with their variant tables, which surfaced two callers — an SDK admission gate and an out-of-tree gate — that read a migrated checker's module-level `IMAGE` constant after building their own mixed generation through a still-surviving flag, and got `None`. Both are fixed. All 44 migrated gates, the 45-record test-run freeze, the aggregate inventory gate, a new two-clean-corpus-build reproducibility check, and the full host suite pass.

## Regression guards

- `just system_image_closure_aggregate_check` — flag-reachability and dual-path rules now cover the full corpus; a newly orphaned flag or a gate silently reacquiring the legacy path fails here first.
- `just system_image_builder_check --exhaustive` — the two-clean-corpus-build check; a caller-output-path leak or a component target-directory collision (CP13/CP14's two prior defects) would reappear as a cross-pass identity mismatch.
- `just system_test_run_check` — the plane/record correspondence and closure-consistency checks now handle a closure shared by two planes without weakening the "wrong plane's image" refusal.

## Decisions

- **A composition's implementation providers, not its own recorded deferral reason, decide whether it can have a closure.** Both `sel4-matrix` and `sel4-c-runtime`'s roadmap-recorded blockers were wrong once actually tested against the closure model; the model itself — `implementation_path()`'s provider cases — is the single source of truth for what a closure can name.
- **Two planes may legitimately share one closure.** `sel4-component-graph` and `sel4-device-plane` both boot the `sel4` image; the aggregate and test-run checks were tightened to allow a shared closure while still refusing a record naming a genuinely different plane's image, rather than forcing an artificial one-closure-per-plane split.
- **A migrated gate's `--no-build`/module-import fallback is not a second build path**, it is a fixed reference to what the surviving legacy flag is documented to produce. Adding it required naming the one external caller by name in a comment, so the fallback cannot silently grow a second caller nobody reviewed.
- **`generate-system-test-runs.py` derives a plane's closure name from the checker's own source** (`CLOSURE = "..."`) rather than assuming it equals the run name, matching how the aggregate gate already treats `check-sel4-component-graph.py` as a special case rather than adding a second hand-maintained mapping.

## Open risks and follow-ups

- [ ] The SDK publication clause — an external consumer building and booting one declared closure without a `slime_os` checkout — is not started. `component_sdk.py` exports a component-development SDK only; no closure resolver, generation builder, image packager, or QEMU runner is exported, and `system_image_closure.py` hard-codes `ROOT`-relative paths throughout.
- [ ] `check-sel4-boot-selection.py` and `check-sel4-root-boot.py` remain on the legacy flag for reasons outside CP15: per-arm `boot_bundle_identity` is test-run data rather than a build key, and the root-boot aggregate has no plane image of its own.
- [ ] 3 gates stay declared dual-path: `check-sel4-demo-plane.py` (boot-selection and wrong-target arms), `check-sel4-generation-plane.py` and `check-sel4-rollback-plane.py` (riscv64 arms; their closures name `qemu-arm-virt` only).
- [ ] The 18 legacy-only `SLIME_*` knobs the aggregate gate enumerates are unchanged by this entry; each should disappear with its last caller.
- [ ] A dedicated source guard against reintroducing a `--*-plane` literal or a checker-owned hard-coded image path — beyond the aggregate gate's flag-reachability and dual-path rules already enforcing it — is not a separate mechanism.
