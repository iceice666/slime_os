## Summary

The 2026-08-07 decision to keep self-built DDSI-RTPS rested on two factual claims that upstream evidence now contradicts: that a self-built Zenoh subset would carry "no upstream leverage", and that only DDS satisfies R1's interoperability target. Zenoh's `zenoh-buffers`/`zenoh-codec`/`zenoh-protocol` crates are `no_std`+`alloc` capable with a dedicated upstream CI check proving it, a separate `no_std`/no-alloc client exists, and REP-2000 lists `rmw_zenoh_cpp` as Tier 1 for Kilted Kaiju and Rolling. R0/R1's transport is now a bounded self-built Zenoh subset. Because the payload is unchanged — `rmw_zenoh` puts classic CDR on the wire through the same typesupport `rmw_fastrtps_cpp` uses — the XCDR/ROSIDL half of R0 survives the pivot untouched; only transport and discovery change.

The contract was reissued as `contracts/rpi5-ros2-demo/v2`, which carries the transport family as a closed discriminator plus one optional profile record per admitted family, so a future transport change is a fixture edit rather than another format. Its gate derives every wire constant from upstream definitions rather than transcribing them, and validates its RIHS01 implementation against an upstream `ros2/rcl` fixture before trusting it. Pursuing this uncovered B69: `just rpi5_artifact_check` had been crashing for some time, and behind that crash sat an admission path that never validated kernel-image target profiles at all.

## Decisions

- Decision: R0/R1's transport is a bounded self-built Zenoh subset implemented as a native `no_std` component. Payload stays classic CDR with the existing ROSIDL/XCDR plan intact.
- Rationale: Four facts, each source-verified. (a) `rmw_zenoh_cpp/src/detail/cdr.cpp` forces `eprosima::fastcdr::CdrVersion::DDS_CDR` and serializes through `rosidl_typesupport_fastrtps_cpp`, so the payload half of R0 is transport-independent and is not re-spent. (b) REP-2000's Kilted Kaiju table lists `rmw_zenoh_cpp` Tier 1 / All Platforms / All Architectures, so "not DDS" no longer means "not really ROS 2" — the argument that carried the 2026-08-07 decision. (c) The minimum wire surface is materially smaller than RTPS: a four-message `INIT`/`OPEN` handshake, `FRAME`, `DECLARE_SUBSCRIBER`, and `PUSH`/`Put` over LEB128 primitives and a 2-byte batch length, versus RTPS submessage framing, GUIDs, parameter lists, and a HEARTBEAT/ACKNACK reliability state machine. (d) The framing is bound-checkable before allocation — the batch length arrives up front and each network message is self-delimiting — which is what R0's fail-before-allocation requirement needs.
- Decision: Move the ROS distribution baseline from Jazzy to Kilted Kaiju.
- Rationale: REP-2000's Jazzy Jalisco middleware table does not list `rmw_zenoh_cpp` at all. Keeping Jazzy would mean claiming compatibility over an RMW that distribution does not tier.
- Decision: R0 implements no discovery: static generation-declared peers, no router, no gossip, no multicast scouting, and no liveliness tokens. The key expression is nonetheless composed in `rmw_zenoh`'s exact format, including the RIHS01 type hash.
- Rationale: This keeps R0's unverified surface at zero while leaving R1 reachable. `rmw_zenoh`'s README states multicast scouting ships disabled and that nodes discover each other through a router's gossip; whether two directly connected peers populate the graph cache without gossip could not be traced through `graph_cache.cpp` and is therefore unproven. Emitting the right key expression costs nothing now and is the thing an `rmw_zenoh` peer matches on later.
- Decision: Carry the transport family as contract data (`transport` discriminator plus optional per-family profiles), retaining the DDSI-RTPS shape in full.
- Rationale: Requested explicitly — userspace mechanisms must be replaceable. A transport frozen into the schema means every reversal costs a format version. Retaining the DDSI-RTPS record is what makes the discriminator meaningful rather than decorative, and R1's peer target may yet name it.
- Decision: Derive every wire constant in the gate instead of freezing literals, and validate the RIHS01 derivation against an upstream fixture first.
- Rationale: REP-2011 was never merged — it is an open draft PR whose own status table lists the reference implementation as "not started" and flags whether the type name belongs in the hash as unresolved — so `ros2/rcl`'s C implementation is the only specification. A copied digest would be unfalsifiable. Deriving it means a topic rename is caught immediately; the negative-control probe confirmed exactly that.
- Rejected alternative: Vendor `zenoh-protocol`/`zenoh-codec` rather than writing a bounded subset. They are genuinely `no_std`-capable, but they require `alloc`, and this repository's component allocator is a 256 KiB bump allocator whose `dealloc` is a documented no-op, so a long-lived session protocol allocating per message would leak monotonically until exhaustion. `zenoh-nostd` needs an async runtime, and `async`/`Poll`/`Waker` appear nowhere in `components/` or `slime-root/src`. Both mechanisms are prerequisites, not details — the same dependency-chain argument the 2026-08-07 entry used to reject X1, applied consistently. Vendoring the codec would also make a non-Zutai schema the source of truth for a cross-process wire format. Reconsider after C10 private memory and a real executor exist.
- Rejected alternative: `zenoh-pico`. Written in C, requires `z_malloc`/`z_realloc`/`z_free` with no no-heap mode in `platform.h`, and its port API is BSD-socket-shaped (`_z_socket_set_blocking`, `_z_socket_close`, per-transport TCP/UDP/TLS functions). Slime has no sockets and components have no C toolchain; it would also be a second wire-format language.
- Rejected alternative: Keep DDSI-RTPS and record the new facts as an audit. Defensible — one frozen OMG specification, Jazzy baseline unchanged, no contract churn — but it spends the same hand-written-codec budget on a larger wire surface for an RMW whose tier advantage has evaporated, and the cost of pivoting grows monotonically with every RP milestone. Zero transport code existed, which made this the cheapest moment it will ever be.
- Rejected alternative: Amend `contracts/rpi5-ros2-demo/v1` in place. Rejected because v1's README states unknown required values need a new contract version, and because RP0/RP1's recorded exit conditions were observed against v1's gate; rewriting it would rewrite frozen evidence.

## Open risks and follow-ups

- [ ] R1 owns two formats R0 does not emit: the `@ros2_lv` liveliness-token grammar with its QoS substring and `/`↔`%` mangling, and — should it need them — the `zenoh::ext` advanced publisher/subscriber paths. Neither is in the Zenoh 1.0.0 specification; both are defined by implementation.
- [ ] Whether two directly connected `mode: "peer"` sessions populate `rmw_zenoh`'s graph cache with no router and no gossip is **unverified**. R1 must establish this by observation before claiming interoperability, and if a router turns out to be required, it must arrive as an exact generation-declared endpoint grant rather than as scouting.
- [ ] Zenoh's wire protocol version is negotiated (`VERSION: u8 = 0x09`, CLOSE/UNSUPPORTED on mismatch) but no cross-minor-release compatibility guarantee was found in the changelog. An upstream bump is a contract change; the v2 gate makes it a loud one.
- [ ] The RIHS01 derivation is verified against `PointCloud2` and `FieldType` only. The canonicalization `rosidl_generator_type_description` applies when building the tree from a `.msg` — specifically field ordering — was not read, so a message shape more complex than the flat scalars R0 admits may need re-verification. The gate rejects any non-scalar field rather than guessing.
- [ ] `contracts/rpi5-ros2-demo/v1` and its gate stay green as historical evidence. If they ever become a maintenance cost, retiring them is a separate decision — they are what RP0/RP1's recorded exit conditions were observed against.
- [ ] No transport code exists. This entry moves a contract and a plan; R0/RP6 implement and observe the behavior.
- [ ] B69 layer 4 raises a question this entry does not answer: how many other admission checks exist as functions nothing calls. A pass looking for unreferenced `require`-bearing helpers in `scripts/check/` would be the natural follow-up.
