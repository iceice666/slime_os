## Summary

`roadmap/` carries two authorities that CLAUDE.md/AGENTS.md already named separately — "completion authority" for the roadmap, "how conclusions were reached" for devlog — but nothing enforced the split, so it collapsed in practice. `00-backlog.md`'s `## Open` section was `(none)`; 99.4% of the file (5,904 of 5,939 lines) was `## Resolved` carrying the full investigation narrative for 68 closed defects, all of which were already the subject of at least one devlog entry (91 devlog entries reference a `B<N>` id; 53 `B<N>`s have a dedicated devlog folder). `02-core-runtime.md` and `07-architecture-portability.md` showed the same pattern on Complete milestones: full `Deliverables`/`Required checks`/`Verification target` sections retained after the work closed, even though `01-foundations.md`'s 24 Complete milestones already used a 12-16 line collapsed form the newer files never adopted. Three defects had no devlog record to point to at all (`B1`, a second `B29` use, and `B52`, whose devlog folder existed but wasn't linked from the entry).

This entry collapses the Resolved/Complete narrative to a fixed five-line form everywhere a devlog link exists, leaves it in place with an annotation everywhere one doesn't, and rewrites the three governing documents (`AGENTS.md`, `roadmap/README.md`, `devlog/README.md`) so the collapsed form is the required shape going forward rather than a one-time cleanup. `roadmap/` fell from 12,120 to 5,191 lines (`00-backlog.md` 5,939→1,204, `02-core-runtime.md` 1,872→1,069, `07-architecture-portability.md` 2,133→722); nothing In-progress, Deferred, Not-started, or Blocked was touched.

## Decisions

- Decision: Compress in place rather than move `00-backlog.md` or split it into an archive file.
- Rationale: `scripts/check/check-devlog.py`'s `roadmap_ids()` builds the legal `Roadmap`-field id namespace from a non-recursive `ROADMAP.glob("*.md")` plus `^#{2,3} (\S+)`. Moving the file into a subdirectory would drop every `B<N>` id from that set and break the 91 devlog entries that reference one; renaming it would require updating ~148 devlog links plus several files the checker doesn't cover (`README.md`, `docs/directions/*`, `docs/capability-matrix.md`, a contract fixture doc, `sel4.md`, `AGENTS.md` itself). An archive file is the same accumulation under a different name — the actual leverage was deleting the duplicated narrative, not relocating it.
- Decision: Collapse to a fixed five-line form (four for backlog entries, five for milestones) rather than a table row.
- Rationale: Measured directly — a `| B68 | … |` table row does not match `^#{2,3} (\S+)`, so converting Resolved entries to a table would silently empty the id namespace the same way moving the file would. The `### B<N> — <title>` heading has to stay a heading.
- Decision: Never reword or renumber an existing `B<N>` or milestone heading, even when compressing everything below it.
- Rationale: `check-devlog.py:273` resolves cross-file links by `partition("#")[0]`, which drops the `#anchor` fragment before checking existence — so an anchor pointing at renamed heading text would go stale silently, with `just devlog_check` staying green. 26 anchored `roadmap/*.md#...` links were inventoried before editing; keeping heading text byte-identical was the only change that avoids auditing all 26 after every edit.
- Decision: Leave `B1`, the second `B29` use, and every In-progress/Deferred/Not-started/Blocked milestone (C9, C10.x, P3, P4, and both P5.4.2-named in-progress sections) completely untouched, with an annotation on the two backlog entries explaining why they're uncollapsed.
- Rationale: `B1` and the second `B29` have no devlog folder; collapsing them would delete their only record, and writing a devlog entry retroactively for a defect with no contemporaneous observation would violate devlog's own evidence rules (`devlog/README.md`'s evidence-rules section, not touched by this change). In-progress work is not this entry's subject — `roadmap/`'s job for unfinished work is unchanged.
- Decision: Give P2.3–P2.6 a distinct "Superseded before closure" template instead of the standard Complete form, and treat this entry as the place their convergence rationale is explained rather than re-litigating it in `07-architecture-portability.md`'s prose.
- Rationale: P2.3–P2.6 never opened their own gate (`just aarch64_isolation_check`/`aarch64_wake_check`/`aarch64_generation_check`/`aarch64_qemu_check` were never built) — P5 superseded the custom-AArch64-kernel route before those checks existed, so there is no observed exit condition to compress into `**Exit condition (observed):**`. The parent P2 status line's older wording — that the sub-slices' deliverables are "retained as the record of what the custom-kernel route required" — predates this cleanup and is left as-is at `07-architecture-portability.md:64`; what changed is that P2.3–P2.6's own bodies no longer *also* carry that full record, because no devlog `Roadmap` field ever cited P2.3–P2.6 (only prose mentioned them), and `devlog/2026-08-09-p5-4-final-kernel-retirement/` already carries the retirement narrative in full. The record didn't move — the duplicate copy of it in the sub-slice bodies was deleted.
- Rejected alternative: Script the compression mechanically.
- Rejected alternative reason: A pre-edit survey found 15+ label-format variants across Resolved entries (`**Fix.**` with a period, inline `**Resolved <date>.**`, dates hidden in heading suffixes on 13 entries, two entries whose closure narrative sits at the body's end while the opening fields still read as open). A script correct for the common case would silently mishandle the tail without a human noticing, which is worse than the duplication it would remove. Every entry was read and collapsed by hand, largest three first (`B46`, `B28`, `B25` — 2,249 of the Resolved section's 5,904 lines) as the first commit, so the riskiest assumption was checked against the smallest, highest-value change before repeating the pattern 60+ more times.

## Open risks and follow-ups

- [ ] `48` Complete milestones across `02`/`07` had no devlog link before this pass (`02`: 15, `07`: 7, plus `01`/`09`'s pre-existing 24/2 which were left alone as already-compressed). All 22 in `02`/`07` were resolved to a real devlog link during compression; if a future audit finds one that was matched to the wrong entry, that is a correctness bug in this pass, not a design gap.
- [ ] `B1` and the second `B29` use remain the sole record of their defects, in full uncompressed prose, inside `00-backlog.md`. If a real devlog entry is ever written for either (contemporaneous evidence surfaces, or the defect recurs and gets investigated fresh), collapse them then rather than leaving both a full entry and a redundant devlog entry.
- [ ] `roadmap/README.md`'s Mermaid diagram and Current-state table were not audited for stale status text as part of this pass; the plan scoped that check to `roadmap/README.md`'s "Updating this roadmap" section only.
- [ ] The id-invariant projection used to verify this pass (`Counter` over `^#{2,3} (\S+)` matching an id-shaped regex) intentionally excludes non-id section-label tokens (`Deliverables`, `Required`, `Exit`, `Planned`, `Verification`, etc.) that shrank as part of this compression. That exclusion was verified against every id currently cited in a devlog `Roadmap` field (161 ids, zero misses) but is not re-verified automatically — a future roadmap section using a new label that happens to look id-shaped could silently join the counted set.
- [ ] `01-foundations.md` and `09-rpi5-ros2-demo.md` were confirmed already in the collapsed shape and left untouched; they were not re-verified against the exact five-line template introduced here, so minor format drift between them and the newly-collapsed `02`/`07` sections may exist.
